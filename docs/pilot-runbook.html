The exact steps, in order, to get one distributor's Tally sales and stock into your ERPNext for one manufacturer, then prove it is correct. Each step says where it happens.

1Give the site a permanent address

Bench terminal Every agent stores this address. If it changes, every distributor's agent stops delivering.

Your API user is on averlonworld.com. If that domain's DNS is on Cloudflare, a named Cloudflare Tunnel gives a fixed address such as erp.averlonworld.com. It uses the same cloudflared you already run, and it needs no open ports or static IP.

bash · on the bench machine
# once: log in and create the tunnel
cloudflared tunnel login
cloudflared tunnel create ssv-erp
cloudflared tunnel route dns ssv-erp erp.averlonworld.com
~/.cloudflared/config.yml
tunnel: ssv-erp
credentials-file: /home/<user>/.cloudflared/<tunnel-id>.json
ingress:
  - hostname: erp.averlonworld.com
    service: http://localhost:8000
  - service: http_status:404
bash · run it as a service so it survives reboots
sudo cloudflared --config ~/.cloudflared/config.yml service install
sudo systemctl enable --now cloudflared

Use port 8000 for bench start, or 80 if the bench runs behind nginx in production mode. Frappe picks the site from the address. If this bench has more than one site, attach the new address to yours with bench setup add-domain erp.averlonworld.com --site <site>. With a single site it is served for any address.

If the domain is not on Cloudflare

Any address that survives a restart works: a reserved ngrok domain run as a service, or a small VPS with HTTPS. It must be HTTPS; the agent's batches are authenticated by signature, not by login.

3Set up ERPNext for the pilot

ERPNext desk Either run the setup script (recommended) or do the same four things by hand.

Option A · setup script

From the ssv-platform folder on any PC with Node 18+. It uses your admin API key, creates only what is missing, and prints the distributor's agent settings at the end. Run the dry run first; it only reads.

PowerShell · ssv-platform folder
$env:ERPNEXT_URL        = "https://erp.averlonworld.com"
$env:ERPNEXT_API_KEY    = "<api key>"
$env:ERPNEXT_API_SECRET = "<api secret>"
node tools\erpnext-setup.mjs --dry-run
node tools\erpnext-setup.mjs --principal-code PATANJALI --stock-group Patanjali

It creates the Brand, the item group, five sample manufacturer items (Dant Kanti 100g and others), the territory chain, a “Distributor” customer group and customer, SSV Settings and the SSV Distributor with its stock-group rule. Then it prints five lines like these:

printed by the script · keep it private
MIDDLEWARE_URL=https://erp.averlonworld.com
MIDDLEWARE_BATCHES_PATH=/api/method/ssv_channel.api.batches
MIDDLEWARE_CONFIG_PATH=/api/method/ssv_channel.api.config
DISTRIBUTOR_ID=DIST-001
AGENT_SECRET=<generated secret>

Option B · by hand

  1. SSV Settings: set Principal Code to PATANJALI.
  2. Items: create the manufacturer's items. Give each an item name that matches the item name in the distributor's Tally, so it maps automatically.
  3. SSV Distributor → New: Distributor ID DIST-001, name and territory. Under Which Tally items belong to this principal, add Stock Group = Patanjali. Save; a secret is generated.
  4. On that distributor: Actions → Show Agent Secret. Copy the five lines it shows.

Consent before the secret

For a real distributor, get the signed data-sharing consent first. Record its date in Data Sharing Consent Date on the SSV Distributor, then send the five lines. The consent template lists exactly what the agent sends.

4Prepare TallyPrime

TallyPrime On the PC that will play the distributor. Educational mode is fine for the pilot.

Educational mode limits dates

TallyPrime in Educational mode only accepts voucher dates on the 1st, 2nd and 31st of a month. Put the test vouchers on those days.

Turn on the XML server

F1 Help → Settings → Connectivity → Client/Server configuration: set TallyPrime acts as to Both, Port 9000. Accept and restart TallyPrime. To check, open http://localhost:9000 in a browser on that PC; it should say TallyPrime Server is Running.

Create a multi-brand distributor company

  1. Alt+K Company → Create: Sharma Distributors, state Maharashtra, GST on. F11: maintain inventory Yes.
  2. Stock groups: Patanjali, then Patanjali Oral Care under it, and Colgate Palmolive. The second brand is there to prove it never reaches your site.
  3. Stock items with opening stock:
    • Dant Kanti 100g under Patanjali Oral Care, 500 Nos
    • Kesh Kanti Shampoo 200ml under Patanjali, 200 Nos
    • Colgate Strong Teeth 200g under Colgate Palmolive, 300 Nos
    Names must match the ERPNext item names exactly for automatic mapping.
  4. Ledgers under Sundry Debtors: Sharma Kirana Store (with GSTIN) and Gupta General Store. A sales ledger Sales GST 18% under Sales Accounts.
  5. Vouchers:
    • F8 Sales to Sharma Kirana Store: 10 Dant Kanti and 5 Colgate on one bill.
    • F8 Sales to Gupta General Store: 4 Kesh Kanti.
    • Alt+F6 Credit Note from Sharma Kirana Store: 2 Dant Kanti returned.

Keep Tally's Stock Summary and Sales Register open; step 6 compares against them.

5Run the agent

Distributor PC The same PC as TallyPrime. No Node or other install needed.

  1. Unzip ssv-agent-0.5.3-win-x64.zip into a folder, e.g. C:\SSVAgent.
  2. Copy .env.example to .env in that folder and fill it in:
C:\SSVAgent\.env
# the five lines from step 3
MIDDLEWARE_URL=https://erp.averlonworld.com
MIDDLEWARE_BATCHES_PATH=/api/method/ssv_channel.api.batches
MIDDLEWARE_CONFIG_PATH=/api/method/ssv_channel.api.config
DISTRIBUTOR_ID=DIST-001
AGENT_SECRET=<from step 3>

TALLY_URL=http://localhost:9000
SYNC_INTERVAL_MINUTES=5
# optional: only read Tally from this date on the first sync
# SYNC_FROM=2026-04-01
# while testing deletions, check every 5 minutes instead of 60
DELETED_CHECK_INTERVAL_MINUTES=5
# any long random string; enables the local status API on 127.0.0.1:4100
LOCAL_API_TOKEN=<random string>
PowerShell · C:\SSVAgent
.\ssv-agent.exe --once     # one sync, prints a report, exits
.\ssv-agent.exe            # keeps running in this window (testing)

Windows may warn Windows protected your PC because the exe is not yet code-signed: More info → Run anyway.

For everyday running, double-click install.cmd in the same folder and accept the Windows prompt. It installs the SSV Tally Connector service: it starts with Windows, restarts itself, keeps the settings in C:\ProgramData\SSVConnector (administrators only) and logs to C:\ProgramData\SSVConnector\logs\agent.log. Close any ssv-agent.exe window first; uninstall.cmd removes it.

Reading the --once report

FieldGood value
rulesSourcemiddleware: the agent fetched the stock-group rule from ERPNext.
firstSyncCompleted, daysReadtrue on the first run, with one day read per day since the company's start (or SYNC_FROM).
upload.vouchers, upload.itemsAbove zero; rejected 0 and no error.
warningsEmpty. An item matching two manufacturers' groups is listed here.

Run from a window, the agent keeps its data and logs in %APPDATA%\SSVConnector, and closing the window stops it. As the service it uses C:\ProgramData\SSVConnector and runs without anyone logged in.

A distributor who sells for several manufacturers

One agent serves all of them through the SSV hub. The hub gives each manufacturer only its own lines. Only the agent's address changes.

  1. Bench terminal Register the distributor on the hub. This writes RL-001.agent.env with the distributor's hub secret:
    bash · in ~/ssv-hub on the server
    cd ~/ssv-hub
HUB_PUBLIC_URL=https://ssv-test.rajlaxmiworld.in node src/admin.js add-distributor RL-001 "Rajlaxmi Solutions"
  2. For each manufacturer: on that manufacturer's site, create the SSV Distributor as in step 3, then link it on the hub with the secret from its Show Agent Secret. read -rs asks for the secret without showing it or saving it in the shell history:
    bash · repeat per manufacturer
    read -rs -p "Agent secret from that site: " HUB_LINK_SECRET; export HUB_LINK_SECRET
node src/admin.js link RL-001 CEAT https://ssv-test.rajlaxmiworld.in DIST-001
unset HUB_LINK_SECRET
node src/admin.js list
  3. Distributor PC Put the lines from RL-001.agent.env into the agent's .env in place of the five lines from step 3. The paths are /agent/v1/batches and /agent/v1/config on the same address.

Each manufacturer still sets Sync Every and Sync Now on its own site. The agent follows the shortest interval, and a Sync Now from any site starts a run.

6Check the data in ERPNext

ERPNext desk Open the SSV Channel workspace.

  1. SSV Sync Health: DIST-001 shows OK with batches and records for today, and Reconciled OK after the first run. From then on, the agent's totals are checked every day; a difference shows as Mismatch and in the daily alert.
  2. SSV Channel Item: Dant Kanti 100g and Kesh Kanti Shampoo 200ml are Mapped to your items. There is no Colgate item at all, because it never left the distributor's PC. Map anything Unmapped by setting its Item.
  3. SSV Secondary Sales for this month, grouped by Distributor and Item. Dant Kanti: sales 10, returns 2, net 8. Kesh Kanti: net 4. Outlets billed: 2.
  4. SSV Distributor Stock, as of today: Dant Kanti 492 (500 − 10 + 2), Kesh Kanti 196. Both should equal Tally's Stock Summary.
  5. Open one SSV Secondary Voucher: the mixed bill shows only its Dant Kanti line, with the retailer linked.

Me, about half a day

  1. Apps: install ERPNext, India Compliance and ssv_channel on the new site, then migrate and run the tests.
  2. Data: restore the test site's latest backup into it, so the pilot's history and your items, classifications and territories come along. Then remove the three test distributors (DIST-001–003) with Delete Channel Data.
  3. Address: add a tunnel route and DNS for the hostname, and send its /agent/v1/ path to the hub.
  4. Settings:
    • SSV Settings: Hold Data Until Consent Is Recorded on, the alert recipients, and the approved agent version with a download link on the new address.
    • Team users with the Sales Manager or Sales User role.
  5. Backups: daily site backups, plus a copy off the server. That needs a destination from you: another server, Google Drive or S3.
  6. Agents: change MIDDLEWARE_URL on each pilot PC, or the hub link, to the new address. The secrets travel with the restored data, so nothing else changes and nothing is re-sent.
  7. Proof: every distributor shows OK and Reconciled OK in Sync Health, and Send Test Alert reaches your inbox.

The test site stays as it is, for trying out changes and for training.

Troubleshooting

What the agent or ERPNext says, what it means, what to do.

You seeCauseFix
TallyPrime is not reachable on http://localhost:9000Tally closed, or the XML server is offOpen TallyPrime with the company loaded; redo the Connectivity setting in step 4.
upload.error: HTTP 401Signature refused: wrong secret or ID, or the PC clock is more than 5 minutes offRe-copy the five lines from Show Agent Secret; set Windows time to automatic.
HTTP 503SSV Settings has no principal codeSet it; the agent retries by itself.
rejected above 0ERPNext refused a batch, e.g. for another manufacturerSSV Ingest Log → status Refused shows the reason.
upload.skipped: first sync in progressThe first sync has not finished all days yetWait or run --once again; it resumes where it stopped. Use SYNC_FROM to start later.
rulesSource: none and nothing uploadedThe agent could not reach ERPNext on its first runCheck MIDDLEWARE_URL opens in a browser on that PC.
Everything stopped after a restartThe site address changed (quick tunnel)Do step 1; then update MIDDLEWARE_URL once.
Items stay UnmappedTally item name ≠ ERPNext item code or nameSet the Item on the Channel Item, or rename to match.
Company blocked: “Repair (rewrite) the company data”Tally's change counter is invalidIn TallyPrime, repair the company data, then sync again.

Security

Do these before any real distributor is connected

  • Administrator password: changed by you on 28 September. Keep it private.
  • Regenerate the admin API secret after setup (User → API Access → Generate Keys). It was shared in chat, and it can do anything the user can. Agents never use it.
  • Each distributor has its own agent secret. Disable a distributor, or rotate its secret with --rotate-secret, to cut it off.
  • Keep the site on HTTPS only. The agent's endpoints accept requests without login, authenticated by signature alone.
